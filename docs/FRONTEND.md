# 中心DC補正モジュールの再利用ガイド

対象は [`native/src/frontend.rs`](../native/src/frontend.rs) の `CenterDcRejector`。USB操作・画面・録音処理から独立したRustモジュールとして、Studioと別の受信ソフトで同じ処理を使うための組込み仕様をまとめる。

この処理は複素IQそのものへ作用する。受信中心にある実際のRF信号にも影響するため、原IQの保持と補正経路の識別を前提とする。PPM校正や局ごとのAFCは別機能である。

## 公開API

```rust
pub const CENTER_DC_CUTOFF_HZ: f64 = 20.0;

impl CenterDcRejector {
    pub fn try_new(sample_rate: f64) -> Result<Self, String>;
    pub fn new(sample_rate: f64) -> Self;
    pub fn reset(&mut self, sample_rate: f64);
    pub fn process_in_place(&mut self, values: &mut [Complex32]);
}
```

- `Complex32` は現在 `rustfft::num_complex::Complex32` を使用する。
- 外部入力のサンプルレートには `try_new` を使う。有限値かつ **40 Hzより大きい**値だけを受け付ける。
- `new` と `reset` は、上記条件を満たすサンプルレートが渡される前提。不正な値ではpanicする。
- `process_in_place` は渡された複素IQ配列を上書きする。原データと別のバッファを渡す。
- 空配列は状態を変えない。I/Qいずれかが非有限のサンプルは出力を0にし、そのサンプルで追従状態を更新しない。最初のブロックが全て非有限なら、有限サンプルを受け取るまで初期化しない。
- 本モジュール自体にON/OFFや機種判定はない。呼出し側で適用を選ぶ。

## 処理式と初期化

サンプルレートを (F_s)、公称コーナー周波数を (f_c=20\,\mathrm{Hz})、IまたはQの入力を (x[n]) とする。I/Qは独立した状態で、内部演算は `f64` を使用する。

\[
a=\exp(-2\pi f_c/F_s),\qquad k=1-a
\]

\[
m[n]=m[n-1]+k\{x[n]-m[n-1]\}
\]

\[
y[n]=\frac{1+a}{2a}\{x[n]-m[n]\}
\]

定常時の伝達関数は次のとおりで、DCで0、ナイキスト周波数で利得1となる。

\[
H(z)=\frac{1+a}{2}\frac{1-z^{-1}}{1-az^{-1}}
\]

20 Hzは公称値であり、有限サンプルレートでの厳密なコーナーはこの式に従う。矩形の除外帯域を作る処理ではない。

最初の非空ブロックでは、I/Qの両方が有限なサンプルの平均をそれぞれ初期値 `m` として使い、そのブロックの先頭から追従・減算する。一定の中心成分が起動時の過渡としてMax Holdへ残ることを抑えるための初期化である。

初期平均は**最初のブロックの内容と長さに依存する**。初期化後はブロック間で状態を維持し、後続ブロックの分割位置によらず同じ逐次演算を続ける。通常の各ブロックで `reset` してはいけない。連続したIQストリームごとに1個のインスタンスを持ち、FFT窓やVFOごとに新設しない。

## 組込み位置

```text
受信した原IQバイト列 ───────→ 原IQ保存・プリトリガバッファ
        │
        └→ 複素IQへ変換 → 任意の中心DC補正 → FFT・ピーク検索・測定・トリガ判定
                                            └→ VFO抽出・復調 → 音声・WAV
```

StudioのRTL-SDR `cu8` 入力は、先頭バイトをI、次をQとして各成分を `(byte - 127.5) / 127.5` へ変換する。別ソフトが既に複素浮動小数点IQを持つ場合は、その正規化規約を確認してからモジュールへ渡す。

以下は、原IQを変更せず処理用バッファを作る組込み例。保存やUSB操作は呼出し側が担当する。

```rust
use rtl_spectrum_studio::frontend::CenterDcRejector;
use rustfft::num_complex::Complex32;

fn processing_iq(
    raw: &[u8],
    rejector: &mut CenterDcRejector,
    apply: bool,
) -> Result<Vec<Complex32>, String> {
    if raw.len() % 2 != 0 {
        return Err("不完全なI/Qサンプルです".into());
    }
    let mut iq: Vec<Complex32> = raw.chunks_exact(2)
        .map(|v| Complex32::new(
            (v[0] as f32 - 127.5) / 127.5,
            (v[1] as f32 - 127.5) / 127.5,
        ))
        .collect();
    if apply {
        rejector.process_in_place(&mut iq);
    }
    Ok(iq)
}
```

呼出し側は、原IQを保存する経路と、返された処理用IQを利用する経路を分ける。トリガ判定を補正後IQで行う場合も、記録する原IQまで補正済みに置き換えない。WAVは復調経路の処理を反映した音声なので、原IQと同義には扱わない。

現時点の共有単位はRustの公開モジュールである。C/C++・C#・Python等から呼べるC ABIや共有DLL、既存 `rtlsdr.dll` と互換なshimは、このモジュールだけでは提供していない。呼出し規約・複素数の受渡し・所有権・エラー処理を定めるアダプターは別の実装対象となる。

## 状態を初期化する境界

次の境界で、受信中の処理が終わってからフィルターを作り直すか `reset` する。

- 受信開始・停止、受信ソース変更。
- 中心周波数・サンプルレート・入力モードなど受信条件の変更。
- 原IQの欠落・非連続なサンプル位置、保存IQのシーク。
- 補正のON/OFF変更。

補正前後の表示履歴を混ぜないよう、切替時にはFFT途中データ、Density、Waterfall、Max/Min/Average、ピーク追従の履歴も扱う。音声キューと遅延した旧frameを区別する世代番号も呼出し側で更新する。USB転送や録音中のロックはこのDSPモジュールの責任範囲に含まれない。

StudioではArm・IQ保存・WAV録音中の変更を拒否し、同じ設定の再送は状態をリセットしない。生IQ再生は再生開始・シーク時に新たな初期平均を作るため、収録中に持っていた補正状態をそのまま復元する保証はない。

## 適用条件とDirect Sampling

現在のStudioでは、補正を要求し、チューナー経路で、有限かつ40 Hzより大きいサンプルレートの場合に適用する。`direct_i` / `direct_q` は補正を迂回する。これは現在採用した適用範囲であり、Direct Samplingの中心成分が存在しないという証明ではない。

入力経路は、実行中のAPI状態または保存IQに含まれる `mode_actual` を優先する。再保存したIQは元の入力メタデータが入れ子になり得るため、Studioでは深さを制限して探索し、既知のモードだけを新しいIQメタデータの上位へ記録する。元情報がない場合は要求設定からの推定であることを示し、実機状態の読戻しへ格上げしない。

RTL-SDR Blogドライバで初回モード切替が入る構成では、先に希望する受信中心へ移ってチューナー経路を確定させ、その後にサンプルレート・帯域などを設定する。設定API成功と、実アナログ帯域・IF・実RFゲインの測定は区別する。`rtlsdr_set_offset_tuning` は対象BlogドライバでBias-T用途に転用されるため、このDC補正の実装に使わない。

## 記録すべき処理条件

StudioはIQの入力メタデータとWAV条件に `frontend_processing` を記録する。別ソフトも、少なくとも次を追跡できるようにする。

| 項目 | 現実装の内容 |
|---|---|
| 方式 | `independent_iq_one_pole_dc_rejection` |
| 要求状態 | `dc_reject_enabled` |
| 処理経路への適用 | `dc_reject_applied_to_processing` |
| コーナー | `cutoff_hz = 20.0` |
| 入力経路の根拠 | API読戻し、保存メタデータ、合成データ、要求設定からの推定を区別 |
| 解析・復調・トリガ | `dc_rejected` または `raw_decoded` |
| 保存IQ | `raw_cu8_unmodified` |
| 初期化 | `first_finite_input_block_mean` |
| 再生・シーク | 補正状態を新たに初期化 |

機種名だけから任意の入力へ自動適用する共通ドライバが完成したという扱いにはしない。適用機種・入力経路・設定・ソフト版を確認するのは呼出し側の役割となる。

## 既知の制約

- 受信中心の実キャリアと、不要な中心DC成分を原理的に識別して選別する処理ではない。AM局を中心に置くと実搬送波を抑え、包絡復調が崩れる場合がある。補正OFFと比較するか、受信中心を局の周波数からずらし、VFOを局へ合わせる。中心近傍の実信号も振幅・位相へ影響を受ける。
- 補正は実際のIQを変える。描画だけのピーク非表示や、ハードウェア内部の原因修正とは区別する。
- 一定の校正値を引く方式ではなく、入力の低周波成分へ追従する。遅い変調、DCを含む信号、信号の断続時にはその特性を評価する。
- 初回ブロックの平均による初期化、ON/OFF・欠落・シークでの再初期化が過渡へ影響する。異なるブロック分割や開始位置からの処理で、開始部までbit一致するとは限らない。
- クリップ・アナログ過負荷・失われたサンプルを回復せず、RF感度やS/Nを改善する機能ではない。非有限値の置換や演算overflow時の出力制限も、受信機保護や校正の代わりにならない。
- Studioは補正適用中の絶対レベル校正表示を無効化する。補正後の数字を校正済みRF測定値として扱わない。
- 実機の中心抑制量・帯域外信号への影響・感度／S/N等の性能数値は本書に記載していない。実施済みと未完了の範囲は [VALIDATION.md](VALIDATION.md) で確認する。原IQ・私的な検証記録はリポジトリに含めない。

配布するライブラリのABI、バージョン互換、対象言語、ライセンス・再配布条件は別途確定する。本書の組込み仕様と、実機での受入れ合格を混同しない。
